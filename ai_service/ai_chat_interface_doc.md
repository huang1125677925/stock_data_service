# AI Agent Chat 接口文档

## 1. 接口基本信息

- **接口路径**: `/api/ai_service/chat/` (假设 ai_service app 被挂载在 `/api/ai_service/`，请根据实际路由调整)
- **请求方法**: `POST`
- **Content-Type**: `application/json`
- **响应类型**: `text/event-stream` (SSE 流式返回)
- **接口说明**: 提供给 Android App 端的大模型对话接口，支持流式返回文本、实时推送工具调用状态和工具执行结果（卡片数据），并与后端 MCP Server 结合使用。

---

## 2. 请求参数 (Request)

### Body 参数
使用 JSON 格式传递参数。

| 字段名   | 类型         | 必填 | 说明                                                                                              |
| :------- | :----------- | :--- | :------------------------------------------------------------------------------------------------ |
| messages | Array<Object> | 是   | 历史消息列表和当前发送的消息。必须包含至少一条消息。列表按时间先后排序，最新的消息放在数组最后。 |

### `messages` 对象结构

| 字段名  | 类型   | 必填 | 说明                                                                      |
| :------ | :----- | :--- | :------------------------------------------------------------------------ |
| role    | String | 是   | 消息发送者的角色。可选值：`user`（用户）, `assistant`（AI助手）, `tool`（工具） |
| content | String | 是   | 消息的具体内容。                                                          |
| tool_call_id | String | 否 | 当 role 为 `tool` 时，需要传入对应的工具调用 ID。 |

### 请求示例

```json
{
  "messages": [
    {
      "role": "user",
      "content": "请帮我查一下贵州茅台（600519.SH）最近5天的股票行情，并进行简要分析。"
    }
  ]
}
```

---

## 3. 响应参数 (Response - SSE)

接口采用 **SSE (Server-Sent Events)** 技术流式推送数据。
每条消息的格式均为标准的 SSE 格式：`data: <JSON_STRING>\n\n`。

### 客户端解析说明

客户端需要监听数据流，并解析 `data: ` 后面的 JSON 字符串。
JSON 对象中统一包含一个 `type` 字段，用于区分不同类型的推送消息：

| `type` 类型 | 说明                                                                 |
| :---------- | :------------------------------------------------------------------- |
| `status`    | **状态推送**。例如模型决定调用外部工具时，推送“正在调用工具...”的提示。 |
| `tool_card` | **工具执行结果**。返回工具的完整名称和执行结果，用于 App 端渲染工具卡片。 |
| `text`      | **流式文本回复**。AI 助手回复的文本片段（Delta），需要客户端拼接显示。  |
| `done`      | **结束标志**。当前对话流结束。                                       |
| `error`     | **错误信息**。对话过程中发生异常时返回的错误信息。                   |

### 推送数据格式详情

#### 1. 状态推送 (`type: "status"`)
当 AI 决定使用工具时推送，用于在界面展示 Loading 状态。
```json
{
  "type": "status",
  "content": "正在调用工具 tushare.stock_data.daily..."
}
```

#### 2. 工具卡片数据 (`type: "tool_card"`)
工具执行完成后推送，包含工具名称和执行结果。
```json
{
  "type": "tool_card",
  "tool_name": "tushare.stock_data.daily",
  "result": "..." // 工具执行的返回结果（如 JSON 字符串或长文本）
}
```

#### 3. 流式文本 (`type: "text"`)
AI 分析后返回的文本片段，客户端需持续将 `content` 拼接到当前回复中。
```json
{
  "type": "text",
  "content": "贵"
}
```
```json
{
  "type": "text",
  "content": "州茅台的"
}
```

#### 4. 结束标志 (`type: "done"`)
表示后端已完成所有的思考、工具调用和文本生成，关闭当前连接。
```json
{
  "type": "done"
}
```

#### 5. 错误信息 (`type: "error"`)
执行中途出现错误时返回。
```json
{
  "type": "error",
  "content": "DeepSeek API 调用失败: 余额不足"
}
```

---

## 4. 异常响应 (非 SSE)

如果请求在建立 SSE 连接之前就发生错误（如参数校验失败），将遵循项目的统一规范返回标准的 JSON 异常数据：

```json
{
  "code": 400,
  "message": "messages 不能为空",
  "timestamp": "2024-03-20T10:00:00.000",
  "data": null
}
```

## 5. 客户端 (App) 接入建议

1. 使用支持 SSE 的网络库（如 OkHttp 的 `okhttp-sse`）。
2. 在发起请求时，设置请求头 `Accept: text/event-stream`。
3. 根据 `type` 字段进行不同的 UI 渲染：
   - 收到 `status` 时，显示“思考中”或“正在查询数据”的动画。
   - 收到 `tool_card` 时，可以将 `result` 解析后展示为一个结构化的卡片（例如表格或行情小部件）。
   - 收到 `text` 时，使用打字机效果逐字/逐句渲染文本内容。
   - 收到 `done` 时，关闭连接并停止加载动画。
